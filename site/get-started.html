Get started

Tessera ships as plain files: tokens.css, bundle.css and bundle.js, which defines window.Tessera. It needs React 18 on the page. There is no package to install and no build step.

Add it to a page

<link rel="stylesheet" href="/tessera/tokens.css">
<link rel="stylesheet" href="/tessera/bundle.css">
<script src="https://cdn.jsdelivr.net/npm/react@18.3.1/umd/react.production.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/react-dom@18.3.1/umd/react-dom.production.min.js"></script>
<script src="/tessera/bundle.js"></script>

For anything you ship, copy the files from dist/ in the repository into your project instead of linking this site.

Mount a component

const T = window.Tessera, h = React.createElement;
ReactDOM.createRoot(document.getElementById('root')).render(
  h(T.Button, { variant: 'primary', iconStart: 'plus' }, 'Create case')
);

Every component, with its props and guidelines, is in Components. index.d.ts has the same guidance as TypeScript hover docs.

Theme

<html data-theme="dark" data-accent="teal" data-font="geist">

// or at runtime
Tessera.setTheme({ accent: 'teal', font: 'inter' });

Modes: light, dark. Accents: indigo (default), cobalt, teal, graphite. Typefaces: geist (default), plex, inter, system. See Themes.

Files

FileWhat it is
tokens.cssEvery token as a CSS variable, light and dark, plus the type classes.
bundle.cssComponent styles, accent and typeface options. Loads the fonts from Google Fonts.
bundle.jsThe components, as window.Tessera. Needs window.React and window.ReactDOM 18.
index.d.tsTypes and usage notes for every component.
tokens.jsonThe source of the tokens, for design tools and other platforms.

Rules for building with Tessera

  1. Only Tessera. Build every screen from window.Tessera components (code) or the Tessera Figma library (design). Don't pull in other component libraries, icon sets or fonts.
  2. Read the card before using a component. Pick by When to use; if Use something else names a better fit, use that instead.
  3. Tokens only. Colours, spacing, radius, type and shadows come from tokens; never hard-code values or use off-scale spacing.
  4. One primary action per view. Destructive actions use the critical tone and a ConfirmDialog.
  5. Write like the product. Sentence case, verb-first buttons, plain error text that says how to fix it (see Content fundamentals).
  6. Missing pieces. If no component fits, compose one from existing components and tokens, label it as composed, and flag it — don't invent new visual styles or add to the system without the owner's approval.
  7. Check your work. Long text truncates or wraps as described under Long content; every interactive element is reachable by keyboard; light and dark both read correctly.
  8. Keep it dense. Use default sizes (32px controls, 16px icons) and the smaller spacing step when unsure. Don't reach for lg sizes, 24px+ padding inside components, or 16px+ text outside titles; page-level layout is the only place for space-24 and above.
